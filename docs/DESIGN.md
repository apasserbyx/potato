# Potato · 产品设计方案 v0.2

> 名称：Potato  
> 目标平台：Android 单平台（手机原生体验）  
> 核心关键词：极简专注、时间账本、自定义节奏、正计时、主动提醒、可信数据  
> 技术方案：Kotlin + Jetpack Compose，本地优先

---

## 1. 一句话定位

**一个打开就能专注、结束后自动记账、在合适的时候轻轻推你一把的 Android 专注计时器。**

它同时支持两种节奏：**土豆钟**（25 分钟专注 + 5 分钟休息）与**正计时**（想专注多久就多久）。它不试图成为任务管理软件，也不靠「树死了」制造愧疚。它把三件事做好：

1. 开始足够快：10 秒内进入第一颗土豆或正计时。
2. 专注时足够静：屏幕上只剩时间和当前任务。
3. 结束之后有账可查：每一分钟自动记录，统计能回答「我的时间去哪了」。

### 目标用户

- 学生、知识工作者、自由职业者。
- 用过 Forest，但不喜欢游戏化压力的人。
- 用过 Focus To-Do / TickTick，但觉得任务体系太重的人。
- 需要「自定义 50/10、90/20 等节奏」而非固定 25 分钟的人。
- 希望有锁屏倒计时、结束提醒、每日/每周复盘的人。
- 需要「正计时/自由专注」：读书、写长文、开会、练习等不适合被 25 分钟打断的场景。

### 核心循环

**计划 → 专注（土豆 / 正计时）→ 恢复 → 自动记录 → 复盘 → 在合适的时间被提醒开始下一轮**

## 2. 市面产品借鉴与取舍

| 产品 | 值得借鉴 | 我们不做 |
|---|---|---|
| **Flow** | 极简原生视觉、快速开始、承诺模式、屏蔽干扰 | 不做纯计时器；保留轻量任务与数据 |
| **Session** | 专注后的反思、Live Activity、自动化、日历整合 | 不做重度自动化和订阅制功能堆叠 |
| **Focus To-Do** | 任务 × 土豆、预估 vs 实际、日/周/月统计 | 不做文件夹 / 项目 / 子任务层级 |
| **Forest** | 用仪式感提升坚持、专注期间离开会中断 | 不做「树会死」的负罪机制；不做强制锁机 |
| **Pomofocus** | 免费、可自定义时长、网页即开即用 | 不做纯 Web；原生通知和锁屏体验是核心 |
| **Focus Keeper** | 简单可调的间隔与进度图 | 视觉和交互需要更当代 |

### 我们的差异化

1. **时间账本**：每个 session 自动落库，暂停时长、提前结束、任务归属都可追溯；不虚报专注时间。
2. **双计时模式**：土豆钟负责「按节奏推进」，正计时负责「不被时长打断」；两种记录统一进时间账本。
3. **主动节奏**：不仅结束时提醒，还能按「专注时段」和用户习惯，在合适的时候提示开始。
4. **可自定义到分钟**：专注 / 短休 / 长休 / 长休间隔 / 自动开始，全部可调，并可视化节奏条。
5. **克制的数据**：统计不是图表堆砌，而是「这周什么时候最专注、哪种时长最适合你」。
6. **不制造愧疚**：中断也记录，休息也鼓励；连续天数可保护，不用损失厌恶绑架用户。

## 3. 设计原则

1. **10 秒内开始**：打开 App 默认就是计时页；点一次即可开始；任务可选填。
2. **专注时只留时间**：运行中隐藏导航、统计、设置，只保留当前任务、倒计时、暂停。
3. **记录不靠用户记忆**：开始即创建 session，结束自动结算；App 被杀也能恢复。
4. **提醒有分寸**：可配置、可静音、有上限、不制造焦虑；通知必须有用。
5. **数据服务于行动**：每个图表都要能回答一个具体问题，否则删掉。
6. **本地优先**：无需注册，默认不上传；导出/导入保证数据属于用户。

## 4. 信息架构

底部 4 个 Tab，其中「习惯」是独立模块（详见 [HABITS.md](HABITS.md)）：

```
专注          习惯          数据          设置
 ├─ 土豆 / 正计时 ├─ 今日习惯    ├─ 今日/周/月   ├─ 我的节奏（预设）
 ├─ 任务选择    ├─ 时段分组    ├─ 趋势图       ├─ 习惯提醒时段
 ├─ 节奏预设    ├─ 次数进度    ├─ 时间分布     ├─ 每日目标
 └─ 完成结算    ├─ 新增/编辑   ├─ 习惯完成度   ├─ 外观/触感
                └─ 习惯详情    └─ 记录明细     └─ 数据导入导出
```

- **任务不是独立 Tab**：通过专注页的任务胶囊打开「今日任务」底部抽屉，避免变成任务管理器。
- **习惯独立 Tab**：习惯是每天重复的节奏，和一次性任务分开；避免塞进专注页造成信息过载。
- **记录与统计合并**：数据页上方看趋势，下方看明细，用一张卡片切换。
- **设置页收纳低频配置**：自定义土豆钟放在「我的节奏」，不打断主流程。

```
┌──────────────────────────────┐
│  专注中                      │

│                              │
│          24:13               │
│       预计 15:42 结束         │

│                              │
```

- 运行中隐藏 Tab 和统计入口，背景进入低对比暖色。
- 显示「预计结束时间」，比单纯倒计时更有时间感。
- 暂停后：数字变灰，显示「已暂停 01:20」；主按钮变「继续」，次按钮「结束本次」。
- 结束本次不弹道德评判，只问「记录为部分完成？」；≥1 分钟即保留记录。
- **禅模式**：运行中点击屏幕任意空白处，只留时间和一个极小的暂停点；再点恢复。适合把手机放在桌上。
- 防误触：结束按钮需长按 0.8 秒或二次确认（设置可开「承诺模式」隐藏结束按钮）。

## 6. 计时与时间记录规则

### 6.1 状态机

```
idle
 ├─ start pomodoro ──→ focus_running ⇄ focus_paused
 │                        ├─ complete ──→ focus_completed ──→ break_running
 │                        └─ end_early ─→ focus_partial ───→ break_running
 └─ start stopwatch ─→ open_running ⇄ open_paused
                          └─ stop ───→ open_completed

break_running
 ├─ complete ──→ idle / next_focus
 └─ skip ──────→ idle / next_focus
```

- 休息结束进入 `idle` 或根据「自动开始下一颗」进入下一轮。
- 长休计数以「完成的专注颗数」为准；长休结束后清零。
- 正计时没有休息阶段；暂停、结束都保留已用时长。
- 一天结束不强制重置计数，但跨天后的下一次专注可重新开始一轮；以「长休后清零」为主规则。

### 6.2 精准计时

**不要用定时回调累加秒数。** 所有时间以绝对时间戳为准：

```kotlin
data class RunningTimer(
    val startedAt: Long,          // epoch ms
    val endsAt: Long,             // epoch ms；正计时为 0
    val pausedAt: Long?,          // 仅暂停态
    val accumulatedFocusMs: Long, // 已完成运行片段之和
)
```

- 土豆钟每次渲染用 `remaining = max(0, endsAt - now)` 计算。
- 正计时每次渲染用 `elapsed = accumulatedFocusMs + (now - segmentStartedAt)` 计算。
- 暂停时把当前片段累加进 `accumulatedFocusMs`；恢复时开启新片段。
- 暂停不改变正计时已用时长；土豆钟暂停会顺延 `endsAt`。
- UI 刷新频率 250ms 足够让进度环顺滑；显示秒数取整。
- App 从后台回到前台时立即重算，不依赖后台心跳。
- 通知在 `endsAt` 时触发；暂停 / 恢复 / 延长时重新排程。
- 计时时间统一存 epoch 毫秒，跨时区/夏令时不受影响。

### 6.3 Session 数据模型

```kotlin
data class Session(
    val id: Long,
    val mode: SessionMode,        // FOCUS / SHORT_BREAK / LONG_BREAK / OPEN
    val status: SessionStatus,    // RUNNING / COMPLETED / PARTIAL / DISCARDED
    val startedAt: Long,
    val endedAt: Long?,
    val plannedSeconds: Int,
    val focusedSeconds: Int,      // 不含暂停
    val pausedSeconds: Int,
    val presetId: Long?,
    val taskId: Long?,
    val taskTitle: String,
    val tag: String,
    val mood: Int?,              // 1 分心 / 2 一般 / 3 专注
    val note: String,
    val source: String,          // timer / manual
    val editedAt: Long?,
)

data class Task(
    val id: Long,
    val title: String,
    val estimatePomodoros: Int,  // 1–20
    val tag: String,
    val dueDate: String?,        // YYYY-MM-DD
    val completedAt: Long?,
    val createdAt: Long,
)

data class Preset(
    val id: Long,
    val name: String,
    val focusMin: Int,
    val shortBreakMin: Int,
    val longBreakMin: Int,
    val longBreakEvery: Int,
    val autoStartBreak: Boolean,
    val autoStartFocus: Boolean,
    val sound: Boolean,
    val isDefault: Boolean,
)
```

### 6.4 时间归属与统计口径

- **专注时长**：`focusedSeconds` 之和，不含暂停和休息；部分完成与正计时都计入实际时长。
- **土豆数**：只统计 `mode = FOCUS` 且 `completed` 的 session；`partial` 与正计时不计颗数，避免虚高。
- **自由专注次数**：`mode = OPEN` 且 `completed` 的 session 数，单独展示。
- **完成率**：`completed / (completed + partial + discarded)`，运行中不计。
- **连续天数**：当天至少有 1 个 `completed` 专注 session（含正计时）。
- **日期归属**：按 `startedAt` 所在本地日期归属（跨午夜 session 归开始日）。设置中可后续增加「凌晨 4 点换日」。
- **手动补记**：`source = 'manual'`，计入统计，但在明细中标注。
- **休息时长**：单独记录，不进入专注时长；可用于「休息依从率」后续分析。

### 6.5 App 被杀 / 崩溃后的「诚实恢复」

这是时间记录可信度的关键。

1. 开始专注时立即写入 `status = running` 的快照。
2. 到 `endsAt` 时系统本地通知照常触发（无需 App 存活）。
3. 用户再次打开 App：
   - 若 `endsAt` 已过：创建一条 `unconfirmed` 记录，并弹出「上次专注在 15:42 结束，这算完成吗？」  
     按钮：**算完成 / 记录为部分完成 / 丢弃**。
   - 若未到 `endsAt`：恢复运行态，剩余时间正确。
4. 不自动替用户「完成」，也不悄悄丢掉记录。界面上写清楚，避免数据不信任。

### 6.6 边界情况

- 后台 / 锁屏：Android 前台服务保持精确计时与常驻通知；AlarmManager 作为服务被杀的兜底。
- 设备重启：BroadcastReceiver 接收 BOOT_COMPLETED 后重新排程；v1 至少保证下次打开可恢复。
- 时区 / 夏令时变化：使用 epoch 时间，不受时区影响；日期归属按本地时区即时计算。
- 暂停超过 10 分钟：发一次温和提醒「计时已暂停」，不重复。
- 同一时间只允许一个运行中计时。
- 剩余不足 1 分钟时结束：弹「再坚持一下？」可延长 1 分钟；不强制。
- 通知权限被拒：App 内显示提示条，不拦截使用；允许跳转系统设置。

## 7. 主动通知与提醒系统

目标：**在正确的时间出现，而不是尽量多出现。**

### 7.1 通知矩阵

| 类型 | 触发 | 文案示例 | 操作按钮 | 默认 |
|---|---|---|---|---|
| 专注结束 | `endsAt` | 这一颗，熟了。休息 5 分钟吧。 | 开始休息 / +5 分钟 / 结束 | 开 |
| 休息结束 | 休息 `endsAt` | 休息结束。下一颗，准备好了吗？ | 开始下一颗 / 延后 5 分钟 | 开 |
| 时段开始 | 设定的专注时段开始后 15 分钟且无 session | 现在是你的专注时段，要开始一颗吗？ | 开始 25 分钟 / 稍后 | 开 |
| 目标提醒 | 每日目标未达成，设定时间（默认 17:30） | 今天还差 25 分钟。留一颗给重要的事？ | 开始一颗 / 今天算了 | 开 |
| 每周复盘 | 周日 20:00 | 这周你专注了 6 小时 40 分，看看规律？ | 查看数据 | 开 |
| 连续保护 | 连续 ≥3 天且在 21:00 尚未专注 | 连续 6 天了，今天哪怕一颗也算数。 | 开始一颗 / 今天休息 | 关 |
| 暂停提醒 | 暂停 >10 分钟 | 计时已暂停 10 分钟，要继续吗？ | 继续 / 结束 | 开 |
| 正计时整点 | 正计时每满 60 分钟 | 你已经专注 1 小时了，记得喝水。 | 继续 / 结束并记录 | 关 |
| 禅模式 | 不通知 | — | — | — |

### 7.2 规则

- **每个时段最多 1 次**开始提醒；全局每天最多 3 条非计时提醒。
- 免打扰时段默认 22:00–08:00；计时结束通知不受此限制。
- 目标未达成但用户当天已放弃时，不再发第二条。
- 连续保护提供「今天休息」选项，主动允许断签，降低焦虑。
- 通知不写「你又没完成」「你的树死了」这类负向文案。
- 点击通知必须深链到对应页面，不做只打开首页的无效通知。

### 7.3 权限策略

- 不在首次启动就索取通知权限。
- 在用户完成第一颗土豆、点击「提醒我结束」时，用带预览的解释卡请求权限：
  > 允许通知，才能在计时结束时提醒你。只发计时和节奏提醒，没有广告。
- 被拒绝后：在专注页顶部显示可关闭的提示条；设置里可重新开启。
- Android 13+ 需 `POST_NOTIFICATIONS`；精确闹钟需 `SCHEDULE_EXACT_ALARM`，被拒时降级为前台服务保障计时。
- Android 12+ 启动前台服务时检查电池优化状态，引导但不得强迫用户关闭省电。
- 国产 ROM（小米 / 华为 / OPPO / vivo）提供「后台运行帮助」页面，解释如何保持计时可靠。

### 7.4 Android 专属能力

| 能力 | 实现 |
|---|---|
| 结束提醒 | 本地通知 + 前台服务 + AlarmManager 兜底 |
| 锁屏倒计时 | 常驻通知 + `setUsesChronometer(true)` / `setWhen(endsAt)` |
| 通知操作按钮 | 暂停 / 继续 / 结束 / 开始休息 |
| 系统免打扰 | 申请 DND 访问权限，或引导用户开启专注模式 |
| 后台保活 | 前台服务；国产 ROM 省电策略需真机验证 |
| 桌面小组件 | v1.1 使用 Glance |

## 8. 数据统计与洞察

### 8.1 三层结构

1. **今天**：我投入了多久？目标完成了吗？
2. **这一周**：我的节奏稳定吗？时间花在哪些事上？
3. **长期**：我什么时候最专注？哪种时长最适合我？

### 8.2 v1 图表

- **今日摘要**：专注分钟、土豆数、自由专注次数、连续天数。
- **7 日柱状图**：每日专注分钟数 + 目标线；点击查看当天；土豆与正计时用不同深浅堆叠。
- **标签分布**：所选周期内各标签的专注时长占比。
- **时段热力图**：周一至周日 × 小时，展示专注分钟密度；月视图使用。
- **记录明细**：按天分组的时间轴，可筛选标签与状态。
- **洞察卡片**（规则计算，不依赖 AI）：
  - 最佳时段：至少 3 个 session 后，取完成率/时长最高的 2 小时区间。
  - 最佳时长：对比 25 分钟与 50 分钟预设的完成率，给出建议。
  - 预估偏差：任务预估土豆数 vs 实际，帮助下次估得更准。
  - 中断模式：暂停次数最多的星期/时段。
  - 数据不足时明确显示「样本不足」，不硬编结论。

### 8.3 数据可信度设计

- 完成、部分完成、放弃在明细中视觉区分。
- 手动补记有标记，统计页可切换「包含手动记录」。
- 修改历史 session 后，统计即时重算；不缓存不可解释的聚合值。
- 导出 CSV 包含原始字段，方便用户在 Excel 中自行核对。

- 开始：**开始专注**

## 11. 技术方案

### 11.1 技术栈

| 层 | 选择 | 理由 |
|---|---|---|
| 语言 / UI | **Kotlin + Jetpack Compose + Material 3** | Android 原生，最可靠的后台计时与通知控制 |
| 架构 | 单 Activity + Compose 状态 | 页面轻，避免过度架构 |
| 状态 | `StateFlow` + 纯函数计时逻辑 | 可测试，UI 只订阅状态 |
| 存储 | `SQLiteOpenHelper` + Repository | 无 ORM 依赖，查询透明，易迁移 |
| 通知 | `NotificationCompat` + 前台服务 + `AlarmManager` | 锁屏倒计时、操作按钮、进程被杀兜底 |
| 计时 | 前台服务 `TimerService` + 绝对时间戳 | 后台/锁屏准确，可恢复 |
| 图表 | Compose Canvas 自绘 | 视觉可控，无第三方图表依赖 |
| 情感化反馈 | `Vibrator` / `HapticFeedback` | 开始、暂停、完成触感 |
| 常亮 | `FLAG_KEEP_SCREEN_ON` | 专注时保持屏幕 |
| 构建 | Gradle + Android SDK 35 | 生成可安装 APK |

**为什么不用跨平台**：只用 Android 时，原生 Kotlin 能直接使用前台服务、精确闹钟、通知操作按钮与 DND 权限，后台可靠性更好，包体也更小。

### 11.4 计时器实现要点

- `TimerStore`（SharedPreferences）持久化当前快照：模式、阶段、状态、`endsAt`、`accumulatedFocusMs`、预设、任务。
- `TimerService` 是前台服务，启动后每秒刷新通知，不负责「累加」时间。
- UI 只根据快照与 `System.currentTimeMillis()` 计算显示，不持有唯一计时真相。
- 每次开始 / 暂停 / 恢复 / 结束都写快照并重排 AlarmManager。
- `TimerAlarmReceiver` 到点后调用幂等的 `finalizeIfDue()`；Service 与 Receiver 谁先到谁结算，后到者直接返回。
- 正计时没有 `endsAt`，以 `accumulatedFocusMs + 当前片段` 计算；进程被杀后根据 `segmentStartedAt` 恢复。
- 结束后写回 session 表，并把快照切到下一阶段或 idle。

### 11.5 通知实现要点

- 通知渠道：
  - `timer_ongoing`：低优先级、常驻、无声，显示锁屏倒计时；
  - `timer_end`：高优先级、结束音与振动；
  - `reminder`：低优先级、静音可选。
- 常驻通知使用 `setUsesChronometer(true)` + `setWhen(endsAt)` 显示倒计时；正计时使用正计时 chronometer。
- 通知操作按钮：暂停 / 继续、结束、开始休息。
- 操作通过 `PendingIntent` 发给 `TimerService`，不依赖 Activity 存活。
- 结束通知深链到 MainActivity，并携带 `sessionId` 打开结算弹层。
- `AlarmManager.setExactAndAllowWhileIdle` 作为兜底；无精确闹钟权限时降级为 `setAndAllowWhileIdle`，并依赖前台服务。
- 国产 ROM（小米 / 华为 / OPPO / vivo）需在设置中提供「后台运行帮助」页面；这是真实存在的可靠性风险。

### 11.6 测试

- **单元测试**：计时时间计算、暂停/恢复、长休周期、正计时累计、跨午夜归属、统计聚合。
- **集成测试**：SQLite CRUD、session 状态转换、导出 JSON。
- **UI 测试**：Compose UI Test 覆盖开始 → 暂停 → 恢复 → 结束 → 记录出现。
- **真机矩阵**：Android 13 / 14 / 15；至少一台国产 ROM 测后台。
- **计时漂移测试**：修改系统时间 / 模拟后台 30 分钟，误差 ≤1 秒。
- **进程被杀测试**：`adb shell am force-stop` 后到点通知仍出现，重新打开可恢复。

- **v1.1**：桌面 Widget（Glance）、周复盘卡片、连续保护、记录编辑、CSV 导出。
- **v1.2**：日历视图、按任务统计预估偏差、快捷设置磁贴。
- **v2**：可选云同步、环境音、专注屏蔽（无障碍服务）、AI 周报。
- 不做或长期不做：复杂项目层级、社交排名、强制锁机、用枯树惩罚用户的养成系统。

### 建议开发顺序

1. **第 1 周**：项目骨架、主题、SQLite、计时状态机、专注页。
2. **第 2 周**：自定义预设、正计时、任务、session 落库、本地通知。
3. **第 3 周**：数据页、记录明细、手动补记、设置、导出。
4. **第 4 周**：前台服务、AlarmManager、崩溃恢复、权限引导、无障碍、真机测试。
5. **第 5 周**：视觉打磨、动效、内测 APK。

### 验收标准

- 锁屏 / 后台 30 分钟后回来，剩余时间误差 ≤1 秒。
- 计时结束通知在系统允许范围内准时触发；点击能回到正确 session。
- 每个完成的专注都出现在记录中，分钟数不含暂停。
- 修改记录后，统计与图表立即一致。
- 导出 JSON 再导入，session 数量与总时长完全一致。
- 1–180 分钟的自定义预设都能正常跑完一轮。
- 正计时后台运行 2 小时，重新打开显示时长误差 ≤1 秒，并可正常结束记录。
- 通知权限被拒时 App 仍可完整使用。
- TalkBack 能读出「剩余 24 分 13 秒，暂停按钮」。
- 深色模式下文字对比度达标，无刺眼纯白块。

## 13. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Android 后台被杀 | 计时不准、通知丢失 | 前台服务 + 精确闹钟 + 国产 ROM 引导 + 打开时恢复 |
| 通知权限拒绝率高 | 主动提醒失效 | 情境化请求、解释价值、拒绝后不骚扰 |
| 功能膨胀成任务管理器 | 失去极简定位 | 任务只保留 4 个字段；项目/子任务不进 v1 |
| 数据被用户不信任 | 不用统计 | 诚实恢复、手动编辑标记、导出原始数据 |
| 正计时被误当成土豆计入 | 统计失真 | 土豆数只算 `FOCUS`；正计时单独计数 |
| 订阅/账号过早引入 | 增加阻力 | v1 完全本地、无账号；后续再加可选同步 |
