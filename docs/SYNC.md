# Potato 多设备同步设计

> 状态：已确认，阶段 1 已完成
> 日期：2026-11-05
> 范围：Android 与 Windows 同一用户的多设备同步；不含账号、云服务和多人协作
>
> 实施进度（2026-11-05）：数据库 v4、同步 UUID、更新时间、墓碑软删除、同步设置/对端/元数据表、备份格式 v3 已完成并通过迁移、清空、备份恢复验证。下一步为 KMP 同步核心与 Android 同步入口。

## 1. 目标

- 同一用户在 Android 手机、Windows 电脑等设备间同步业务数据。
- 设备在同一局域网内直连，不经过云端、不需要账号。
- 两端都是完整对等端：可以计时、管理任务、打卡习惯、查看统计。
- 离线可用；重新连上后自动合并双方数据。
- 删除不会因为另一台设备离线而“复活”。

## 2. 非目标

- 运行中的计时状态跨设备镜像。
- 自定义习惯图标文件、导入的音频文件跨设备传输。
- 通知权限、通知渠道、当前选中任务/节奏等设备偏好同步。
- 跨时区日期换算。
- 后台常驻实时同步。
- 多人共享、好友、权限模型。

## 3. 同步范围

### 3.1 参与同步的业务数据

| 数据 | 规则 |
|---|---|
| 专注记录 | 只同步 `COMPLETED` 和 `PARTIAL`；排除 `RUNNING`、`DISCARDED` |
| 任务 | 标题、预估、标签、截止日期、完成状态 |
| 节奏 Preset | 名称、专注/短休/长休、长休间隔、自动开始、声音开关、默认标记、排序 |
| 习惯 Habit | 名称、颜色、类型、目标、单位、重复星期、提醒方式/时间/开关、备注、排序、归档状态、创建时间 |
| 习惯打卡 HabitLog | 日期、状态、专注秒数、次数、来源、完成时间 |
| 每日目标 | `dailyGoalMinutes` |
| 提醒时间 | 早/中/晚的分钟数与开关；习惯自身的提醒配置随 Habit 同步 |

### 3.2 不参与同步

- 运行中的计时器状态、前台服务状态、当前阶段。
- 全局习惯提示音、提醒强度、App 直接播放开关、计时提示音。
- 屏幕常亮、默认模式、当前选中任务/节奏、已完成计数、整点提醒状态。
- 通知权限、通知渠道、渠道代际、免打扰状态。
- 稍后提醒、上次提醒时间、通知已提示标记。
- 自定义图标文件、导入音频文件、任何 `media:` / `system:` URI。

### 3.3 自定义资源的表现

- 习惯的 `color`、内置图标/emoji 选择参与同步。
- `iconImagePath` 永远不参与同步。
- 远程设备收到 `iconType = IMAGE` 但没有本地图片时，**仅在显示层**使用内置兜底图标；不要修改实体字段，避免把兜底值同步回源设备。
- 习惯的 `soundKey` 保留在设备本地；远程设备使用本机默认/全局提示音。
- 因此同一习惯在不同设备可以有不同的自定义图标和提示音，这是有意设计。

## 4. 拓扑与发现

- 两两对等同步：每台设备都可以作为客户端和服务器。
- 支持多台已配对设备；同一时刻与任意一台可达设备同步。
- 自动发现：mDNS 服务 `_potato._tcp`，广播设备名、随机端口和能力版本。
- 手动兜底：输入 IP 和端口。
- Windows 防火墙需要允许 Potato 的入站连接；首次启动给出引导。

## 5. 配对与安全

1. 设备 A 打开“配对”，显示一次性 6 位配对码（5 分钟有效）。
2. 设备 B 在局域网中发现 A，或手动输入 IP；输入配对码。
3. 双方通过配对码认证首次密钥交换，交换自签名证书指纹并固定。
4. 配对成功后双方各自签发长期设备令牌；令牌只保存在安全存储中。
5. 后续同步使用 TLS + 设备令牌，只接受已配对设备。
6. 解除配对后，双方撤销令牌并删除对端游标；下次连接必须重新配对。

安全原则：无账号不等于无认证；不信任“同一 Wi-Fi”本身。

## 6. 数据模型改造

### 6.1 稳定身份

现有 SQLite 使用本地自增 ID。跨设备同步需要稳定身份：

- 为 `sessions`、`tasks`、`presets`、`habits`、`habit_logs` 增加 `sync_id TEXT UNIQUE`（UUID）。
- 保留本地整数主键，继续服务现有外键。
- 同步载荷中的引用使用 UUID：
  - 专注记录引用 `task_sync_id`、`preset_sync_id`、`habit_sync_id`。
  - 习惯打卡引用 `habit_sync_id`。
- 接收端通过 UUID 映射到本地 ID；缺失的父实体先导入父实体，或暂缓子记录。

### 6.2 版本与删除

- 所有同步实体增加 `updated_at INTEGER`。
- 增加 `deleted_at INTEGER` 作为墓碑。
- DAO 查询默认过滤 `deleted_at IS NULL`。
- 删除任务、删除节奏、删除记录、清空记录改为软删除并写入墓碑。
- 习惯“移除”仍是归档，不是删除；归档状态作为普通字段同步。
- 墓碑保留策略：MVP 永久保留；个人数据量小，避免回收导致复活。

### 6.3 同步设置

参与同步的设置不使用 `SharedPreferences` 作为同步真源，而是新增表：

```sql
CREATE TABLE sync_settings (
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL,
  updated_at INTEGER NOT NULL,
  deleted_at INTEGER
);
```

首版只放：

- `daily_goal_minutes`
- `habit_morning_minutes`
- `habit_afternoon_minutes`
- `habit_evening_minutes`
- `habit_morning_enabled`
- `habit_afternoon_enabled`
- `habit_evening_enabled`

本地读取仍可镜像到 `SettingsStore`，但修改时必须同时更新 `sync_settings.updated_at`。

### 6.4 配对与游标

```sql
CREATE TABLE sync_peers (
  device_id TEXT PRIMARY KEY,
  device_name TEXT NOT NULL,
  token_hash TEXT NOT NULL,
  certificate_fingerprint TEXT NOT NULL,
  last_sync_at INTEGER,
  last_cursor INTEGER,
  created_at INTEGER NOT NULL,
  revoked_at INTEGER
);
```

每个已配对设备独立保存游标；首次同步使用全量，后续使用增量。

### 6.5 数据库版本

- 数据库版本从 3 升级到 4。
- 迁移时为现有行生成 UUID 和 `updated_at = created_at`（或当前时间）。
- 备份格式从 2 升级到 3，包含同步身份和墓碑字段；旧备份仍可导入并生成新 UUID。

## 7. 同步协议

### 7.1 混合策略

1. **首次同步 / 修复同步**：全量业务数据。
2. **日常同步**：只交换游标之后发生变化的实体和墓碑。
3. **修复**：设置页提供“修复同步”；游标异常、实体数量异常或用户手动触发时执行全量同步。

全量载荷使用 JSON + gzip，业务数据不含媒体文件，规模可控。

### 7.2 同步会话

双方在一次同步会话中：

1. 认证并确认协议版本。
2. 交换各自的全量或增量数据页。
3. 按实体规则合并。
4. 应用远端变更并返回确认。
5. 更新各自的游标。

分页建议每页 500 个实体；会话可中断、可重试；操作必须幂等。

### 7.3 合并规则

| 实体 | 规则 |
|---|---|
| 专注记录 | 按 `sync_id` upsert；`updated_at` 新者胜；墓碑胜于并发更新 |
| 任务 / 节奏 | 按 `sync_id` upsert；`updated_at` 新者胜；同一毫秒按设备 ID 排序 |
| 习惯共享字段 | 按 `sync_id` upsert；`updated_at` 新者胜 |
| 习惯本地字段 | `iconImagePath`、`soundKey` 不参与合并 |
| 习惯打卡 | 键为 `(habit_sync_id, date)`；任意一方为 `COMPLETED` 时完成态优先；都完成时取最新 `completed_at`；否则取最新 `updated_at` |
| 同步设置 | 按 key 比较 `updated_at`，字段级 LWW |
| 删除 | 墓碑优先于并发更新，避免离线设备复活已删除数据 |

时钟策略：使用设备 UTC 毫秒；同一毫秒用设备 ID 打破平局。局域网设备时钟通常接近；手动全量修复用于异常情况。

### 7.4 同步触发

- App 回到前台时，如果存在已配对且可达的设备，自动尝试同步。
- 设置页提供“立即同步”。
- 第一版不做后台常驻同步，不要求两台设备一直在线。
- 运行中的计时不会阻塞同步，因为计时状态不参与同步。

## 8. Windows 客户端

### 8.1 技术路线

- Kotlin Multiplatform 共享模块：模型、同步 DTO、协议、合并规则、校验。
- Android 保留现有 SQLiteOpenHelper 和 Compose UI，只接入共享同步核心，避免一次性重写数据库和界面。
- Windows 使用 Compose Desktop 实现独立 UI；复用土豆配色、排版和交互模式，不强行共享 Android Compose 代码。
- Windows 使用 SQLite（JDBC）保存同等业务数据；存储层平台各自实现，合并逻辑共用。

### 8.2 Windows MVP

- 专注计时 / 正计时。
- 任务管理。
- 习惯查看、编辑、打卡。
- 数据统计。
- 局域网配对与同步。
- Windows 系统通知 + App 内提示音。
- 关闭窗口时最小化到系统托盘，计时继续运行。
- 不包含：自定义图标/音频导入、备份恢复、高级设备设置。

### 8.3 Windows 运行方式

- 数据目录：`%LOCALAPPDATA%\Potato`。
- 前台打开时执行同步；托盘计时不改变同步触发策略。
- 后续再评估开机自启和安装包签名。

## 9. Android 端入口

设置页新增“设备同步”：

- 开关：启用同步。
- 本机设备名。
- “配对新设备”：显示配对码。
- “输入配对码”：连接已发现的设备。
- “已配对设备”：名称、最后同步时间、解除配对。
- “立即同步”和“修复同步”。
- 状态：未启用 / 未配对 / 正在同步 / 成功 / 对端离线 / 网络错误。

配对期间两台设备都需要打开 Potato；局域网直连不做后台服务。

## 10. 边界情况

- 两台设备同时编辑同一任务：LWW。
- 一台设备完成打卡，另一台跳过：完成态优先。
- 一台设备删除任务，另一台离线编辑：墓碑优先，不复活。
- 清空记录：生成墓碑；确认弹窗保留；同步后其他设备也清空。
- 新设备首次配对：全量同步。
- 两台以上设备：每台与可达的已配对设备两两同步；最终一致；不要求所有设备同时在线。
- 设备重装：生成新的设备身份，旧配对失效。
- 时钟偏差：同毫秒用设备 ID 打破平局；异常时全量修复。
- 父实体未到达：先导入父实体，或暂缓子记录，不接受悬空引用。
- 同步中断：分页可重试，实体 upsert 幂等。
- Android 省电限制：只在前台同步，不依赖后台常驻。
- Windows 防火墙：首次启动引导放行。

## 11. 实施顺序

### 阶段 1：数据基础

- 数据库 v4：UUID、`updated_at`、墓碑、同步设置表、同步对端表。
- DAO 软删除过滤；任务/节奏/记录/清空改为墓碑。
- 迁移测试；备份格式 v3。
- 合并规则单元测试。

验收：旧数据无损迁移；删除不会在本地查询中出现；备份可往返。

### 阶段 2：同步核心与 Android

- 新建 KMP 共享模块：模型、DTO、协议、合并、校验。
- TLS 证书、配对码、设备令牌、mDNS 发现、手动 IP。
- 全量/增量同步、游标、修复同步。
- Android 设置页同步入口与已配对设备管理。
- 双机联调、断网重试、冲突用例测试。

验收：两台 Android 设备可在同一 Wi-Fi 下完成配对、双向同步、删除传播和修复同步。

### 阶段 3：Windows MVP

- Compose Desktop 界面：专注、习惯、数据、设置。
- 系统通知、App 内音频、托盘计时。
- Windows SQLite 存储与同步核心接入。
- 与 Android 联调。
- 生成可安装的 Windows 包。

验收：Android 与 Windows 可以互相配对、同步业务数据；Windows 可以独立计时和打卡；样式与 Android 一致。

### 阶段 4：加固

- 多设备（3 台以上）、时钟偏差、超大记录量、同步中断恢复。
- 安全审查：令牌存储、证书固定、解除配对、日志脱敏。
- 版本兼容策略与协议版本升级。
- 真机/真实 Windows 网络矩阵测试。
