# Potato 改进计划书 v1.0

> 基于当前已实现的 v1.0 Android 版本
> 目标：让提醒真正被看见、被听见，并补上习惯养成所需的自定义能力与数据安全

---

## 0. 结论摘要

当前 Potato 已经具备完整可用的主链路：

- 土豆钟 + 正计时
- 自定义节奏
- 轻量任务
- 习惯（计时型 / 次数型）
- 早/中/晚汇总提醒
- 数据记录与基础统计
- 本地存储、导出、深色模式

它现在的主要问题不是「功能不够多」，而是**提醒存在感、可自定义程度、数据安全和发布成熟度**不够。

优先级最高的改进：

1. **提醒升级**：自定义提示音、自定义习惯图标、授权引导、稍后提醒、独立提醒、通知渠道诊断。
2. **可靠性**：数据库操作移出主线程、通知权限与渠道状态检测、OEM 后台适配、自动化测试。
3. **数据安全**：备份导入、图片/声音随备份迁移、版本化恢复。
4. **习惯深度**：详情页、热力图、撤销、排序、归档恢复、习惯统计。
5. **发布准备**：Git 版本管理、release 签名、CI、崩溃日志、Play 政策检查。

## 0.1 已确认的产品决策（2026-11-05）

- **提示音**：采用推荐方案。
  - 全局习惯提醒默认使用统一的「习惯提示音」。
  - 独立提醒可以为单个习惯单独设置提示音。
  - 第一版先支持内置音效 + 系统铃声选择器；本地音频导入作为后续增强。
  - 提供试听和「发送测试提醒」。
- **自定义图标**：可以替换习惯图标。
  - 内置矢量图标库。
  - 保留 emoji。
  - 支持从本地相册上传图片并裁剪为习惯图标。
  - 自定义图标在习惯卡片和独立提醒通知的 large icon 中展示。
- **提醒时间**：新增自定义提醒时间，同时保留原有的早/中/晚汇总模式。
  - 习惯可选择「跟随时段汇总」或「独立提醒」。
  - 独立提醒可设置具体时间。
  - 旧习惯保持原有时段汇总，不需要重新配置。
- **追加提醒**：默认关闭，是否开启由用户决定。开启后每个时段最多追加一次。
- **视觉/主题**：本次只做习惯图标个性化，不包含 App 桌面图标换肤。

## 1. 当前版本评估

### 做得好的部分

- 计时以绝对时间戳为准，暂停/恢复逻辑可靠。
- 前台服务 + AlarmManager 兜底，App 被杀后可恢复。
- 土豆钟、正计时、习惯计时统一进入专注记录。
- 习惯支持计时型与次数型，并可按星期重复。
- 习惯计时自动打卡，提前结束保留实际时间。
- 提醒按早/中/晚汇总，避免每个习惯单独刷通知。
- 本地优先、无账号；数据可 JSON 导出。
- 土豆图标与土豆配色已经形成统一视觉。

### 当前的主要短板

- 习惯提醒只有普通通知，容易被忽略；没有自定义声音和声音预览。
- 习惯图标只有 8 个固定 emoji，颜色只有 4 个固定选项。
- 提醒没有操作按钮、没有稍后提醒、没有失败后的补救提醒。
- 创建提醒时不会主动要求通知权限；用户可能完全收不到提醒。
- 无法检测用户是否把通知渠道静音/关闭。
- 没有每个习惯的独立提醒时间，只有时段汇总。
- 没有习惯详情、历史热力图、最佳连续、撤销记录。
- 任务完成后从列表消失，无法查看、编辑、恢复或删除已完成的旧任务。
- 数据只能导出，不能导入恢复。
- 数据库调用仍在主线程执行，数据量增长后可能卡顿。
- 没有 Git 仓库、release 签名、CI、崩溃日志和 UI 自动化测试。
- 部分设置交互（时间选择器）仍是系统默认样式，与整体视觉不一致。

## 3. 重点专题：让习惯提醒真正被看见

### 3.1 产品目标

提醒要做到三件事：

1. **能被听见**：允许选择明显但不过度打扰的提示音。
2. **能被认出来**：每个习惯有自己的图标/颜色。
3. **能被处理**：收到提醒后可以直接开始、稍后或跳过，而不是只能关掉。

同时尊重用户之前确定的「汇总提醒、每时段最多一次」原则：
- 默认仍然保持汇总提醒。
- 重要习惯可以选择独立提醒。
- 追加提醒是可选项，不默认强推。

### 3.2 提醒模式

每个习惯增加「提醒方式」：

- **跟随时段汇总**（默认）
  - 仍然是早上/下午/晚上一条汇总
  - 使用全局习惯提醒音
  - 适合普通习惯
- **独立提醒**
  - 每个习惯单独设置具体时间
  - 支持独立提示音、自定义图标、通知操作
  - 适合「吃药」「关键练习」等重点习惯

同一时刻出现多条独立提醒时：
- 通知可以分别展示
- 但同一分钟内最多只有一个声音，其余通知静音，避免声音叠加
- 或者合并成一条摘要，具体策略在实现前确认

### 3.3 提示音设计

选项建议：

1. **内置声音**
   - 3–5 个短音效：土豆叮、轻木鱼、薯片脆响、柔和风铃等
   - 时长 < 2 秒，不刺耳，可循环但默认只播放一次
2. **系统铃声**
   - 使用 Android RingtoneManager 选择系统提示音
   - 需要保存 URI 的可持久化权限
3. **本地音频导入**
   - 从文件选择器导入 mp3/ogg/wav
   - 复制到 App 私有目录，避免外部文件被删除后失效
   - 限制大小（例如 < 2MB）与时长（例如 < 30 秒）
4. **预览按钮**
   - 设置页与习惯编辑页都能试听
   - 试听不改变真实提醒渠道

提醒强度：

| 强度 | 行为 | 适用 |
|---|---|---|
| 轻柔 | 无声音，仅通知 + 轻震动 | 办公室、图书馆 |
| 标准 | 自定义提示音 + 标准震动 + 通知 | 默认 |
| 醒目 | 高优先级 heads-up + 自定义提示音 + 较强震动 | 重要习惯 |

### 3.4 技术约束：通知渠道不能改声音

Android 8.0+ 的 NotificationChannel 一旦创建，**声音和重要级别不能由 App 直接修改**。因此不能简单地在设置里改一个值然后继续用旧渠道。

推荐实现：

- 通知渠道 ID 按「声音 + 强度」版本化：
  - `habit_reminder_v2_<soundKey>_<level>`
  - 例如 `habit_reminder_v2_chime_standard`
- 用户选择新声音/强度时，创建对应新渠道并以后使用新渠道。
- 旧渠道标记废弃并从设置中隐藏或删除；旧 ID 仅用于兼容期。
- 全局汇总提醒使用全局声音渠道。
- 独立提醒根据习惯选择声音/强度使用对应渠道。
- 同一首声音 + 同一强度复用同一个渠道，避免渠道数量膨胀。
- 对导入的音频，渠道 ID 使用文件内容 hash 或持久化 key，避免文件名冲突。
- 渠道创建后立即检查 `NotificationManager.getNotificationChannel(id)`：
  - importance 是否为 NONE
  - sound 是否为 null
  - 是否被用户手动关闭
  - 给出「去系统设置恢复」入口

### 3.5 通知操作与稍后提醒

汇总提醒：
- 打开习惯
- 稍后 15 分钟
- 今天不再提醒

独立提醒：
- 开始计时（计时型）
- +1（次数型，可直接从通知增加一次）
- 稍后 10 分钟
- 今天跳过

稍后提醒实现：
- 不需要改数据库里的习惯时间
- 使用一次性 AlarmManager 或 WorkManager 排程
- 持久化 snooze 记录，重启后仍有效
- 每个提醒最多稍后 2 次，避免无限推迟
- 稍后提醒使用原习惯的图标和声音

是否增加「未完成后追加一次提醒」：
- 默认关闭
- 用户可在设置里为每个时段开启
- 最多追加一次，避免骚扰

### 3.6 自定义习惯图标

支持三种来源：

1. **内置图标库（推荐默认）**
   - 12–20 个统一线性图标：书、水、跑步、冥想、写作、睡觉、目标、学习等
   - 矢量图标，跨设备一致
2. **Emoji**
   - 保留现有选择，作为快速个性化
   - 不作为唯一方案
3. **本地图片**
   - 使用 Android Photo Picker 选择
   - 方形裁剪，压缩为 256×256 WebP/PNG
   - 保存到 App 私有目录
   - 删除习惯时清理对应图片
   - 导出备份时一起打包
   - contentDescription 使用习惯名称，而不是图片本身

通知中的表现：
- **系统状态栏小图标不能使用彩色自定义图片**，这是 Android 限制。
- 独立提醒通知使用习惯图片作为 **large icon**，小图标继续使用 Potato 单色图标。
- 汇总提醒继续保持 App 图标。
- 要看到每个习惯的独立图标，需要启用「独立提醒」；这是取舍。

### 3.7 权限与可靠性引导

开启提醒时必须检查：

1. `POST_NOTIFICATIONS` 是否已授权（Android 13+）
2. App 通知总开关是否开启
3. 习惯通知渠道 importance 是否不是 NONE
4. 渠道声音是否被关闭
5. 是否处于免打扰（只提示，不绕过）
6. 精确闹钟权限是否可用（无法精确时提示可能延迟）

提示方式：
- 开启提醒时弹出说明并请求权限
- 设置页显示「通知已静音 / 声音被关闭」并可直接跳转渠道设置
- 添加「发送测试提醒」按钮
- 国产 ROM 省电策略仍通过帮助页引导

### 3.8 数据模型调整

```text
habits 新增：
  reminder_mode          SLOT / INDEPENDENT
  reminder_minutes       独立提醒的分钟数
  sound_key              内置/系统/导入声音标识
  sound_uri              系统铃声或导入音频 URI
  alert_level            GENTLE / STANDARD / STRONG
  icon_type              BUILTIN / EMOJI / IMAGE
  icon_value             内置图标名或 emoji
  icon_image_path        自定义图片相对路径
  per_habit_actions      是否显示通知操作

新增 reminder_jobs（稍后提醒/追加提醒）：
  id, habit_id, trigger_at, kind, sound_key, created_at, status
```

全局设置新增：
- 默认习惯提示音
- 默认提醒强度
- 是否允许追加提醒
- 试听/测试提醒入口

### 3.9 阶段验收标准

- 用户开启提醒时，如果没有通知权限，会被引导授权。
- 用户可以选择提示音并当场试听。
- 真实提醒在锁屏、后台、App 进程被杀后仍按设置播放。
- 通知渠道被静音时，设置页能检测到并引导恢复。
- 汇总提醒仍按早/中/晚只发一条。
- 独立提醒支持自定义图标，通知中显示对应 large icon。
- 稍后提醒可用，重启后仍有效。
- 同一分钟多个提醒不会同时播放多个声音。
- 真机测试覆盖小米/华为/OPPO/vivo 至少各一台。

## 6. 风险与注意事项

| 风险 | 说明 | 对策 |
|---|---|---|
| 通知渠道不可修改 | 声音/重要级别创建后固定 | 版本化 channel，按声音+强度创建 |
| 用户静音渠道 | App 无法强制恢复 | 检测并引导，不绕过用户设置 |
| 导入音频权限失效 | 外部 URI 可能过期 | 复制到 App 私有目录，保存内部副本 |
| 自定义图片体积 | 备份/存储膨胀 | 裁剪压缩到 256px，限制数量 |
| 多渠道数量膨胀 | 每个声音/强度组合一个渠道 | 复用渠道，限制自定义声音数量 |
| 同分钟多条提醒声音叠加 | 用户体验差 | 同分钟只允许一条发声，其余静音/合并 |
| OEM 后台限制 | 国产 ROM 可能拦截提醒 | 前台服务、精确闹钟、引导页、真机测试 |
| Play 政策 | exact alarm / FGS / 通知用途需要申报 | 发布前做政策核查 |
| 数据迁移损坏自定义资源 | 图片/音频路径丢失 | 备份包含资源，导入时校验 |
| 过度提醒 | 用户反感 | 默认汇总一次，追加提醒必须显式开启 |

## 7. 已确认与剩余决策

### 已确认

1. **提示音范围**
   - 全局默认习惯提醒音。
   - 独立提醒可以为单个习惯单独设置提示音。

2. **提示音来源**
   - 第一版：内置 3–5 个音效 + 系统铃声选择器。
   - 本地音频导入放到后续增强，不作为第一版阻塞项。

3. **自定义图标**
   - 采用：内置矢量图标库 + Emoji + 本地图片上传。
   - 自定义的是**习惯图标**，不包含 App 桌面图标换肤。

4. **提醒时间**
   - 同时保留两种模式：
     - 跟随时段汇总（原有早/中/晚）
     - 独立提醒（每个习惯自定义具体时间）
   - 旧习惯默认继续使用原时段，不需要重新配置。

5. **自定义图标的通知表现**
   - 独立提醒使用习惯图标作为 large icon。
   - 汇总提醒继续使用应用图标。
   - 系统状态栏小图标只能使用单色图标，这是 Android 的限制。

### 推荐默认值（可后续调整）

- 提醒强度：默认「标准」；重点习惯可选「醒目」。
- 追加提醒：默认关闭；开启后每个时段最多追加一次。
- 同分钟多个独立提醒：只允许一个播放声音，其余静音，避免声音叠加。
- 提醒声音试听不写入通知渠道；真实提醒才使用对应渠道。
- 所有提醒遵循系统静音和免打扰，不绕过用户设置。

### 仍待你确认

- 是否在第一版就提供「未完成追加一次」的开关？
  - 推荐：提供开关，默认关闭。
- 「醒目」提醒是否允许 heads-up 通知？
  - 推荐：允许，但需要用户在首次开启时明确确认。
